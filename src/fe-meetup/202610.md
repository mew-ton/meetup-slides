## "VoidZero" とは

- Vue / Vite の作者 **Evan You** が 2024 年に設立した企業
- Vite / Vitest / Rolldown / Oxc など, フロントエンドのビルド基盤ツールを手がける
- 2026 年 6 月, チームごと **Cloudflare に合流** した

---

## VoidZero のニュース

**Vite+ 1.0 が正式リリースされた**

- 9/28 公開. MIT ライセンスの OSS
- 依存している公開リポジトリは **2,600 以上**, 週 DL は **200 万目前**
- ただし本人たちも **「機能はまだ揃っていない」** と明言
  (リモートキャッシュや `vp release` などは今後の版で対応予定)

<!-- _footer: "出典: [Announcing Vite+ 1.0 (VoidZero)](https://voidzero.dev/posts/announcing-vite-plus-1-0)" -->

## "Vite+" とは

- VoidZero が開発する, フロントエンド開発ツールの **全部入りパッケージ**
- ビルド / テスト / コード検査 (Lint) / 整形を **`vp` という 1 つのコマンド** で扱う
- Node.js のバージョン管理やパッケージマネージャーの選択まで, `vp` が面倒を見る

## Vinext

2026/09/28

---

## "Vinext" とは

- Next.js (Vercel が開発する React のフレームワーク) のアプリを,
  **Vite の上で動かす** ための互換フレームワーク
- Cloudflare が開発. 既存の Next.js プロジェクトをそのまま動かせることを目指す
- 2026 年 2 月, Cloudflare のエンジニアが AI を使い **1 週間で作った実験** が出発点

---

## Vinext のニュース

**Vinext 1.0 がリリースされた**

- 9/28 に公開
- Cloudflare は **「本番利用に耐える」** と位置づけた

<!-- _footer: "出典: [Next.js applications, powered by Vite: introducing Vinext 1.0 (Cloudflare Blog)](https://blog.cloudflare.com/vinext-nextjs-on-vite)" -->

---

## Next.js との互換

| 機能 (Next.js 16 系) | v1.0 |
| --- | --- |
| App Router / Pages Router | ○ |
| Server Components / Server Actions | ○ |
| API ルート / ミドルウェア | ○ |
| Cache Components | △ |

- 主要機能のテストでの互換率は **99% 超**
  (Cache Components は集計の対象外)

<!-- _footer: "出典: [Next.js applications, powered by Vite: introducing Vinext 1.0 (Cloudflare Blog)](https://blog.cloudflare.com/vinext-nextjs-on-vite) / [cloudflare/vinext (GitHub)](https://github.com/cloudflare/vinext)" -->

---

## 何が変わるのか

- Next.js は, 独自のビルドの仕組み (webpack / Turbopack) と一体で使うのが前提だった
- Vinext により, **Next.js のコードを Vite のエコシステムで動かす** 選択肢が本番レベルになった
- ただし全機能が揃ったわけではない

## IANA

2026/09/28

---

## IANA (Internet Assigned Numbers Authority) とは

- インターネットの **番号と名前** を一元管理する機関 (ICANN の関連組織が運営)
- ドメインの最上位 (ルートゾーン), IP アドレスの割り当て, ポート番号などを管理
- いくつかの予約ドメインのアクセス先のサイトも運営している

---

## IANA のニュース

**example.com のサイトを刷新 — 「テストや監視には使わないで」と明記**

- 9/28, example.com などの予約ドメインのサイトを刷新した
- ページでは, **ドキュメントでの例示用** であり,
  **テストや死活監視などの運用には使わない** よう案内している

<!-- _footer: "出典: [IANA's email about why example.com changed (Oliver Dunk)](https://www.oliverdunk.com/2026/09/30/iana-reply)" -->

---

## アクセスのほとんどは "自動アクセス"

- IANA によると, example.com へのアクセスの **大半は人ではなくプログラム**
- その出どころは, example.com を **「確実につながる宛先」** として扱うコード
  - テストコードの通信先
  - CI での疎通確認, 死活監視の宛先
  - サンプルをコピーしたまま残った設定
- **例示用の名前** が, 世界中で **インフラ代わりに使われてしまっている**
  → だからこそ「テストや監視には使わないで」と明記された

<!-- _footer: "出典: [IANA's email about why example.com changed (Oliver Dunk)](https://www.oliverdunk.com/2026/09/30/iana-reply)" -->

---

## ○ フォームのプレースホルダー

<label style="font-size: 1.1em;">メールアドレス
<input type="email" placeholder="you@example.com" style="font-size: 1em; padding: 0.3em 0.5em; width: 14em;">
</label>

```html
<input type="email" placeholder="you@example.com" />
```

- 入力例を見せる = **例示** そのもの. 本来の用途どおり
- 表示するだけで, どこにもアクセスしない

---

## × テストコード

```ts
test("ユーザー一覧を取得できる", async () => {
  // NG: 実在する外部サイトにアクセスしてしまう
  const res = await fetch("https://example.com/api/users");
  expect(res.ok).toBe(true);
});
```

- 実害がなくても, テストが **外部へのアクセス** に依存してしまう
  → 相手の都合 (刷新, 停止, 応答の変化) で **テストが壊れる**
- そのアクセス自体が, IANA の負担になっている自動アクセスの一部になる

---

## △ じゃあアクセスしなければいいのか？

```ts
// テストでフォームに自動入力するメールアドレス
await page.getByLabel("メールアドレス").fill("taro@example.com");
```

- このコード自体は, どこにもアクセスしない
- でも **書いてしまうと真似される** — 人にも, AI にも
- **"例示" ではない用途は目的外**. アクセスの有無に関わらず使わない

---

## まとめ — 例示なら OK, それ以外は NG

| 使い方 | example.com |
| --- | --- |
| ドキュメント・サンプルコードの例示 | ○ |
| フォームのプレースホルダー | ○ |
| テストコード (通信をモックしていても) | × |
| 疎通確認・死活監視 | × (言うまでもなく) |

- テストで通信が必要なら, **モックするか, 自分で立てたローカルサーバー** に向ける
- 死活監視は, **自分で管理する宛先** に向ける

---

## 用途ごとの予約ドメイン (RFC 2606)

| ドメイン | 用途 |
| --- | --- |
| `example.com` `example.net` `example.org` | ドキュメントでの例示 |
| `.example` | ドキュメントでの例示 |
| `.test` | テスト用 |
| `.invalid` | **必ず無効** (失敗のテスト用) |
| `.localhost` | 自分自身 (ループバック) |

- テストでは **`.test` / `.invalid`** を使う

<!-- _footer: "出典: [RFC 2606: Reserved Top Level DNS Names (IETF)](https://www.rfc-editor.org/rfc/rfc2606)" -->

## JPEG XL

2026/10/06

---

## "JPEG XL" とは

- JPEG の後継を狙って作られた, 国際標準 (ISO/IEC 18181) の画像フォーマット
- 同じ画質なら JPEG より **30〜50% 小さい**. 劣化のない圧縮や, 明暗差の大きい表示 (HDR) にも対応
- 既存の JPEG を **画質を落とさずに** JPEG XL へ変換し, 元に戻すこともできる

---

## JPEG XL のニュース

**Chrome と Firefox が, 標準で JPEG XL を表示できるようになった**

- 10/6 公開の **Chrome 155** で, 実験フラグなしで表示できるようになった
- 10/13 公開の **Firefox 158** でも, 標準で有効化された
- これで **主要 3 エンジンすべて** が JPEG XL に対応した

<!-- _footer: "出典: [Shipping JPEG XL in Chrome (Chrome for Developers)](https://developer.chrome.com/blog/jpeg-xl-in-chrome) / [Firefox 158 release notes for developers (MDN)](https://developer.mozilla.org/en-US/docs/Mozilla/Firefox/Releases/158)" -->

---

## 他ブラウザとの互換性

| ブラウザ | JPEG XL の表示 |
| -------- | -------------- |
| Chrome   | 155〜          |
| Safari   | 17〜           |
| Firefox  | 158〜          |

- 非対応のブラウザでは **画像が表示されない** — 単に置き換えると壊れる
- `<picture>` で JPEG などの代替を併記すれば, **段階的に導入できる**

---

## 段階的に導入するには

対応ブラウザは JPEG XL を, 非対応ブラウザは JPEG を表示する

```html
<picture>
  <source srcset="photo.jxl" type="image/jxl" />
  <img src="photo.jpg" alt="..." />
</picture>
```

## Deno

2026/10/09

![bg 15%](./_assets/logos/deno.svg)

---

## "Deno" とは

- Node.js の作者 **Ryan Dahl** が, 2018 年に発表した JavaScript の実行環境
- TypeScript をそのまま実行でき, ファイルやネットワークへのアクセスを **許可制** にできる
- ホスティングサービス **Deno Deploy** と, パッケージ置き場 **JSR** も運営している

---

## Deno のニュース

**Deno の開発チームが, まるごと Cloudflare に合流する**

- **Deno 本体**: 今後 1 年間は, 月 1 回のバグ修正・セキュリティ更新を続ける
  → その後, **チームとしての開発は終了**. OSS として残し, 引き継ぎは歓迎するとした
- **Deno Deploy**: 6 か月間運用したのち **終了**. 有料顧客には移行支援
- **JSR**: 運営を続ける. 基盤は Cloudflare へ移す

<!-- _footer: "出典: [Deno is joining Cloudflare (Deno Blog)](https://deno.com/blog/cloudflare)" -->

---

## Cloudflare で何をするのか

- Deno が開発していた, サーバー実行基盤 **celld** を
  Cloudflare Workers の OSS 版ランタイム **workerd** に統合する
- 狙いは, Cloudflare Workers と同じ仕組みを **自分のサーバーでも動かしやすくする** こと
- Deno 単体の実行環境とホスティングを続けるのではなく,
  **Cloudflare の基盤に力を集める** 判断

---

## Cloudflare に集まる JavaScript の基盤

- **2026/06** — VoidZero (Vite / Vitest / Rolldown / Oxc) が合流
- **2026/09** — Vite+ 1.0 / Vinext 1.0 を公開
- **2026/10** — Deno が合流

いずれも OSS は維持するとしているが,
JavaScript の主要な基盤が **1 社に集まりつつある** ことは意識しておきたい

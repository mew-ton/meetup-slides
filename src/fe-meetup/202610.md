## VoidZero

2026/09/28

![bg 15%](./_assets/logos/voidzero.png)

## "VoidZero" とは

- Vue / Vite の作者 **Evan You** が 2024 年に設立した企業
- Vite / Vitest / Rolldown / Oxc など, フロントエンドのビルド基盤ツールを手がける
- 2026 年 6 月, チームごと **Cloudflare に合流** した

---

## "Vite+" とは

- VoidZero が開発する, フロントエンド開発ツールの **全部入りパッケージ**
- ビルド / テスト / コード検査 (Lint) / 整形を **`vp` という 1 つのコマンド** で扱う
- Node.js のバージョン管理やパッケージマネージャーの選択まで, `vp` が面倒を見る

---

**Vite+ 1.0 が正式リリースされた**

- 9/28 公開. MIT ライセンスの OSS
- 依存している公開リポジトリは **2,600 以上**, 週 DL は **200 万目前**
- ただし本人たちも **「機能はまだ揃っていない」** と明言
  (リモートキャッシュや `vp release` などは今後の版で対応予定)

## example.com

2026/09/28

---

## "example.com" とは

- 説明やサンプルコードで使うために **予約されている** 例示用のドメイン
- 1999 年の RFC 2606 (インターネットの標準文書) で, 例示用として定められた
- IANA (ドメインや IP アドレスを管理する団体) が管理している

---

## example.com のニュース

**ほぼ何もないことで有名なページが, 大きく作り変えられた**

- 9/28, 英語だけの静的なページから, **JavaScript で複数の言語を表示** する形へ
- 当初は 5 秒ごとに言語が切り替わったが,
  10/3 から **全言語を最初から並べる** 形に変わった
- ページには **「テストや死活監視には使わないでほしい」** という注意も書かれている

<!-- _footer: "出典: [Example.com Just Launched The Biggest Redesign In Decades (DebugBear)](https://www.debugbear.com/blog/example-dot-com-redesign-history)" -->

---

## なぜ変えたのか

- IANA の担当者によると, アクセスの **大半はプログラムによる自動アクセス**
- 本文を HTML と JavaScript に分けると, 自動アクセスは JavaScript を取りに来ない
  → **配信するデータ量を減らせる**
- そもそも example.com は **説明に使うための名前**. Web サーバーは「好意で」動かしているだけ

<!-- _footer: "出典: [IANA's email about why example.com changed (Oliver Dunk)](https://www.oliverdunk.com/2026/09/30/iana-reply)" -->

---

## 開発者側で気をつけること

- 疎通確認や死活監視の宛先に, example.com を **使わない**
  (実際に今回, ページの中身が大きく変わった)
- テストで使うなら, 自分で管理するサーバーを用意する
- ドキュメントの例として使う, という **本来の用途** はこれまでどおり

## Sindre Sorhus / Hono

2026/10/01

---

## "Sindre Sorhus" とは

- ノルウェーの OSS 開発者. 15 年にわたり OSS を公開し続けている
- npm に **1,000 を超えるパッケージ** を公開している
- `chalk` (ターミナルの文字色付け) や `ky` (HTTP クライアント) など,
  意識せず依存していることが多い小さな部品の作者

---

## "Hono" とは

- 和田裕介 (yusukebe) さんが作った, 日本発の Web フレームワーク
- Web 標準の API だけで書かれており, **どの実行環境でも同じコードが動く**
  (Cloudflare Workers / Deno / Bun / Node.js など)
- 軽量・高速で, サーバー側の API を書く用途で広く使われている

---

## Sindre Sorhus / Hono のニュース

**有名 OSS が, 外部からの Pull Request (PR) の受付を相次いで止めた**

- 10/1, Sindre Sorhus 氏が **全リポジトリで外部 PR を無効化**
  「AI のせいで. 私たちが知っていた OSS は, 続いている間は楽しかった」
- 10/5, Hono も本体リポジトリで外部 PR を無効化
  「この時代, PR はもう機能しない. 別の形で貢献してほしい」
- どちらも **開発自体は継続**. Issue (不具合報告・要望) は引き続き受け付ける

<!-- _footer: "出典: [Sindre Sorhus (X)](https://x.com/sindresorhus/status/2105693826690298314) / [Yusuke Wada (X)](https://x.com/yusukebe/status/2107027870019445007)" -->

---

## なぜ PR を閉じるのか

- AI を使えば, PR は **数秒で作れる**
- しかしメンテナーが読んで判断するには, 1 件ごとに **人の時間がかかる**
  → 質の低い PR が大量に届き, レビューが回らなくなった
- GitHub も 2026 年 2 月, リポジトリ単位で
  **PR を無効化 / コラボレーター限定にする設定** を追加している

<!-- _footer: "出典: [New repository settings for configuring pull request access (GitHub Changelog)](https://github.blog/changelog/2026-02-13-new-repository-settings-for-configuring-pull-request-access/)" -->

---

## OSS への関わり方が変わる

- 「まず PR を送る」が, 貢献の入り口として **通用しなくなりつつある**
- 代わりに求められるのは, **再現手順つきの質の高い Issue**
- コードを変えるのは, **信頼関係のある少数のメンバー** という形へ

## JPEG XL

2026/10/06

---

## "JPEG XL" とは

- JPEG の後継を狙って作られた, 国際標準 (ISO/IEC 18181) の画像フォーマット
- 同じ画質なら JPEG より **30〜50% 小さい**. 劣化のない圧縮や, 明暗差の大きい表示 (HDR) にも対応
- 既存の JPEG を **画質を落とさずに** JPEG XL へ変換し, 元に戻すこともできる

---

## JPEG XL のニュース

**Chrome と Firefox が, 標準で JPEG XL を表示できるようになった**

- 10/6 公開の **Chrome 155** で, 実験フラグなしで表示できるようになった
- 10/13 公開の **Firefox 158** でも, 標準で有効化された
- これで **主要 3 エンジンすべて** が JPEG XL に対応した

<!-- _footer: "出典: [Shipping JPEG XL in Chrome (Chrome for Developers)](https://developer.chrome.com/blog/jpeg-xl-in-chrome) / [Firefox 158 release notes for developers (MDN)](https://developer.mozilla.org/en-US/docs/Mozilla/Firefox/Releases/158)" -->

---

## 一度は消されていた

- Chrome は 91〜109 でフラグ付きの試験実装をしていたが,
  **「エコシステムの関心が薄い」として Chrome 110 (2023 年) で削除** した
- その後, Safari 17 (2023 年) が先に対応
- 今回の Chrome は, **Rust で書き直したデコーダー (jxl-rs)** を採用
  → 画像の読み込み処理は攻撃の入り口になりやすく, 安全性を重視した

---

## 他ブラウザとの互換性

| ブラウザ | JPEG XL の表示 |
| -------- | -------------- |
| Chrome   | 155〜          |
| Safari   | 17〜           |
| Firefox  | 158〜          |

- 非対応のブラウザでは **画像が表示されない** — 単に置き換えると壊れる
- `<picture>` で JPEG などの代替を併記すれば, **段階的に導入できる**

---

## 段階的に導入するには

対応ブラウザは JPEG XL を, 非対応ブラウザは JPEG を表示する

```html
<picture>
  <source srcset="photo.jxl" type="image/jxl" />
  <img src="photo.jpg" alt="..." />
</picture>
```

## Deno

2026/10/09

---

## "Deno" とは

- Node.js の作者 **Ryan Dahl** が, 2018 年に発表した JavaScript の実行環境
- TypeScript をそのまま実行でき, ファイルやネットワークへのアクセスを **許可制** にできる
- ホスティングサービス **Deno Deploy** と, パッケージ置き場 **JSR** も運営している

---

## Deno のニュース

**Deno の開発チームが, まるごと Cloudflare に合流する**

- **Deno 本体**: 今後 1 年間は, 月 1 回のバグ修正・セキュリティ更新を続ける
  → その後, **チームとしての開発は終了**. OSS として残し, 引き継ぎは歓迎するとした
- **Deno Deploy**: 6 か月間運用したのち **終了**. 有料顧客には移行支援
- **JSR**: 運営を続ける. 基盤は Cloudflare へ移す

<!-- _footer: "出典: [Deno is joining Cloudflare (Deno Blog)](https://deno.com/blog/cloudflare)" -->

---

## Cloudflare で何をするのか

- Deno が開発していた, サーバー実行基盤 **celld** を
  Cloudflare Workers の OSS 版ランタイム **workerd** に統合する
- 狙いは, Cloudflare Workers と同じ仕組みを **自分のサーバーでも動かしやすくする** こと
- Deno 単体の実行環境とホスティングを続けるのではなく,
  **Cloudflare の基盤に力を集める** 判断

---

## Cloudflare に集まる JavaScript の基盤

- **2026/06** — VoidZero (Vite / Vitest / Rolldown / Oxc) が合流
- **2026/09** — Vite+ 1.0 / Vinext 1.0 を公開
- **2026/10** — Deno が合流

いずれも OSS は維持するとしているが,
JavaScript の主要な基盤が **1 社に集まりつつある** ことは意識しておきたい

## GitHub Actions

2026/10/08

---

## "GitHub Actions" とは

- GitHub に組み込まれた, テストやデプロイを自動で実行する仕組み (CI/CD)
- リポジトリに設定ファイル (ワークフロー) を置くと, push などをきっかけに動く
- npm への公開やデプロイのため, **トークンなどの秘密情報を持たせる** ことが多い

---

## GitHub Actions のインシデント

**"GhostAction" — 3 万を超えるリポジトリに, 認証情報を盗むワークフローが仕込まれた**

- 乗っ取られた **約 1,900 の GitHub アカウント** から,
  `security-audit.yml` という **それらしい名前** のワークフローが push された
- 10/8〜9 の 2 日間で, **約 3,000 のユーザー / 組織の 3 万超のリポジトリ** が標的に
- GitHub は 10/9 から実行をブロックしたが, それまでに **実行され, 流出も確認** された

<!-- _footer: "出典: [GhostAction Returns: 772 Repos Hit, 30k More in Oct (GitGuardian)](https://blog.gitguardian.com/ghostaction-github-actions-supply-chain-attack-returns/)" -->

---

## 何が盗まれたのか

- ワークフローは, リポジトリの **Git 履歴をすべて** 取得してから中身を探す
  → 過去のコミットに一度でも入った秘密情報も対象になる
- 狙われたのは, クラウドの認証情報や GitHub トークンなど
- 8〜9 月にも同じ手口の波があり, 当時は **承認待ちで止まった** 実行が多かった
  — 10 月の波では, それが **実際に動いてしまった**

---

## 教訓

- 身に覚えのない **ワークフローファイルの追加** がないか確認する
  (`Security Audit` という名前のワークフローは要注意)
- 秘密情報は **一度でもコミットしたら, 消しても履歴に残る**
  → コミットしてしまったら, 削除ではなく **失効・再発行** する
- GitHub アカウントそのものが攻撃の入口になる. **アカウントの保護も CI の一部**

## React / Next.js

2026/10/14

![bg 15%](./_assets/logos/react.png)
![bg 15%](./_assets/logos/nextjs.svg)

---

## "React" とは

- Meta (旧 Facebook) が開発した, UI を組み立てる JavaScript ライブラリ
- 画面を **コンポーネント** という部品に分けて組み立てる
- **React Server Components (RSC)** で, 一部の部品をサーバー側で動かせる

---

## "Next.js" とは

- Vercel が開発する, React ベースのフルスタックフレームワーク
- サーバー側の処理まで含めて, React で Web アプリを作れる
- React Server Components を実用化した代表的な存在

---

## 2025 年 12 月に何が起きていたか

- React Server Components に, **認証不要で任意のコードを実行できる** 脆弱性が発覚
  (通称 **React2Shell**. 深刻度スコア CVSS で最高の 10.0)
- Next.js をはじめ, RSC を使うフレームワークが軒並み影響を受けた
- 公開直後から **実際の攻撃** が大規模に観測された

---

## React / Next.js のインシデント

**Next.js が臨時のセキュリティ更新 — 認証なしでコードを実行できる脆弱性が再び 2 件**

- 最も深刻な Critical (CVSS 9.5) が 2 件, その次の High が 1 件
  - `use cache` 関数の処理で, **任意のコード実行** (RSC 側の問題)
  - 画像最適化の **SVG 処理** で, 任意のコード実行 (画像処理ライブラリの問題)
  - Server Actions で, サーバーを応答不能に追い込める (DoS 攻撃)
- 9 月の定例更新に入る予定が, **依存ライブラリ側の都合で延期** されていた

<!-- _footer: "出典: [Next.js Security Update for Upstream Vulnerabilities (Next.js Blog)](https://nextjs.org/blog/nextjs-security-update-october-14-2026)" -->

---

## 今すぐ確認すること

- Next.js は **16.4.1 / 15.5.28** 以上へ
- React の RSC 関連パッケージを直接使っているなら,
  **19.0.9 / 19.1.10 / 19.2.9 / 19.3.1** のいずれか以上へ
- `use cache` の問題には **回避策がない**. 使っていなくても更新が推奨されている
- 10/15 時点で悪用の報告はない — **攻撃が始まる前に** 塞いでおきたい
